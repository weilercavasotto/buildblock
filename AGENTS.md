# BuildBlock

Web-based 3D building game (LEGO-like): place blocks and wheels on a grid, press Play, drive the
creation under physics. Stack: TypeScript, Vite, Three.js, Rapier (`@dimforge/rapier3d-compat`).

Full documentation lives in [`docs/`](docs/README.md). Update it when you change behaviour.

## Git workflow

Details in [docs/branches.md](docs/branches.md). The rules:

- **Never commit on `main`.** All work (features, fixes, adjustments, docs) happens on `develop` or on a task branch started from `develop` (`feature/…`, `fix/…`, `docs/…`, `chore/…`). Check `git branch --show-current` before the first edit of a task; if it says `main`, switch to `develop` first.
- A task branch is merged into `develop` when the task is done (`git merge --no-ff`, then delete the branch).
- **Finishing a task always means a commit on `develop`** (directly, or by the merge of the task branch), once `npm run build` passes and the docs are updated. This is standing permission: do not ask before committing at the end of a task.
- **Do not push unless asked**, and `main` only receives `develop` in a release the user asks for.

## Commands

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # tsc type-check + vite build (run before finishing a change)
```

There is no test suite yet; verify changes in the browser (see "Verifying changes").

## Layout

- `src/main.ts`: bootstrap, mode switching (menu/build/play), main loop, active-save autosave
- `src/types.ts`: `Part`, `Vec3`, cell helpers
- `src/build/`: `grid.ts` (data model), `build-mode.ts` (picking, ghost, place/remove)
- Scenery (ramps, obstacles): `SCENERY_PARTS` in `src/constants/scenery.ts`, catalog parts on one fixed body (`PhysicsWorld.buildScenery` / `addStructuralColliders`), built only for the main menu (`new PhysicsWorld(grid, true)`); Play is just the floor; edit that list to change them
- `src/play/`: `physics-world.ts` (grid -> Rapier), `vehicle-controller.ts` (the player's part keys -> engines, wheels and the other parts)
- `src/play/play-effects.ts` + `src/play/particles.ts`: Play effects (wheel dust, engine smoke, engine shaking; `PhysicsWorld.level` from `VehicleController.level`); the placement bounce is in `BuildMode.animateBounces`; tunables in `FX` / `COLORS.fx` (`src/constants/`)
- `src/parts/part-defs.ts`: visuals/dimensions of every part
- `src/menu/`: main-menu background (`menu-scene.ts`: random car + orbiting camera, `random-build.ts`: coupe / pickup / propeller / rocket / sled (skis + thrusters) kinds with random paint, plus the standing builds windmill / lighthouse / rocketship (`staticBuild` path) and the plane (own builder, points to +z, `orient(x, z)` turns a wing's axes; the menu keeps a plane straight, brakes it at the roaming edge and replaces it when it stops) (`staticBuild` path: no base, wheels or engine), with headlights, glass, tiles, sirens and barrels at `RANDOM_BUILD` chances (the autopilot switches lamps and sirens on); a part with an orientation uses `facing(type, direction)`; keep new builds valid: `Grid.add` drops what does not fit, mind the stud lattice for 0.5-wide parts; the menu autopilot drives rotors, pistons and thrusters)
- `src/constants/`: design tokens and tunables (colours, spacing, typography, physics, game, text); `theme.ts` publishes them as CSS variables
- `src/styles/main.css`: all CSS, tokens only; buttons get their raised look from the **Button skin** section at the end (add a new button's selector to its lists; tokens `BUTTON`, `COLORS.button`, `OVERLAYS.sheen`)

- `src/build/history.ts`: undo/redo (`begin`/`commit`/`run`); wrap every user edit of the grid in one step (Ctrl/Cmd+Z / Y)
- `src/ui/loading-screen.ts`: loading overlay (the stacked logo with the name + progress bar + label) for scene changes; wrap such transitions in `loading.run([{ label, run }, …])` (`main.ts` does it for menu ⇄ build and at boot); timings in `LOADING`, strings in `TEXT.loading`
- `src/ui/confirm-dialog.ts`: reusable modal confirmation (`confirmDialog`); use it instead of `window.confirm`
- `src/camera-limits.ts`: `limitCamera` (limits the polar angle so the camera stays above the ground at its current distance, instead of pushing it up: the zoom distance stays exact; call before `controls.update()`, also used by `ZoomControl`) and `panArea` + the `area` of `limitCamera` (while building the orbit target stays within the creation widened by `CAMERA.panMargin`, so the zoom is always about the creation; not while playing), and `keepCameraAboveGround` (safety net after the update)
- `src/ui/zoom-control.ts`: zoom buttons/slider synced with the wheel; limits in `CAMERA.minDistance/maxDistance`

## Conventions

- The project was renamed from BlockLab to BuildBlock. Everything uses the new name (the `localStorage` keys `buildblock.*`, the dev global `window.__buildblock`, the Pake app id `com.weilercavasotto.buildblock`). `src/storage-migration.ts` (imported first by `main.ts`) moves a browser's old `blocklab.*` keys to the new ones once; the only old name left is `STORAGE.legacyKey` (`blocklab.v1`, the single-slot save of the first version, which `save.ts` still migrates). A new storage key goes in `constants/` with the `buildblock.` prefix.
- **Never hard-code colours, sizes, spacing, fonts, tunable numbers or UI strings**: add/use a token in `src/constants/`
  (see [docs/constants.md](docs/constants.md)). CSS only uses `var(--...)`; Three.js colours go through `hexToNumber(COLORS...)`.
- **All in-game text is English** (HUD, help, labels, `lang="en"`).
- **File names are kebab-case** (`build-mode.ts`); classes inside stay PascalCase.
- The `Grid` is the single source of truth; the simulation never mutates it. Stop discards the physics world.
- The game starts in the main menu. Edits autosave only to the active save (`activeSave` in `main.ts`);
  set it to `null` around `grid.load/clear` so loading does not rewrite (and re-date) a save.
- UI font is Orbitron (self-hosted, imported in `main.ts`, token in `typography.ts`); it is wide, so keep sizes modest and buttons `nowrap`.
- Mouse: left = place on press / drag to keep placing the same part (`Stroke` in `build-mode.ts`, one part apart, any part) on the starting face's plane (never moves the camera), right click = remove / right drag = pan, middle drag = rotate,
  scroll = zoom (`controls.mouseButtons` in `main.ts`; click-vs-drag logic in `build-mode.ts`).
- `index.html` hides the whole body until `main()` adds `html.ready` (after `applyTheme()`), and paints the page `#0a0e18` (= `COLORS.surface.vignette`) meanwhile, so no unstyled flash on first load; keep that colour in sync.
- The version shown in the menu comes from `package.json` (`__APP_VERSION__`, defined in `vite.config.ts`).
- User-provided text (save names) is rendered with `textContent`, never `innerHTML`.
- Cell `[x, y, z]` centre is world `(x, y, z)`; ground top is `y = -0.5`; valid cells have `y >= 0` and x, z within `buildRange(cells)` (`-n/2 … n/2 - 1`) and `0 <= y <= n - 1` of the game's grid size (`Grid.setSize`; inside the floor grid, whose squares are exactly one cell: lines at n ± 0.5).
- Shared geometries/materials are created once in `part-defs.ts`; do not dispose them per instance.
- Adding a part type: follow [docs/adding-a-part.md](docs/adding-a-part.md).

## Physics gotchas

- Connected blocks must stay **one rigid body** with one collider per block; do not joint individual cubes.
- Multi-cell parts (the large wheel `bigWheel`, 2 x 2 cells that its orientation leads to): `partCells` / `partCentre` in `types.ts`; position visuals / bodies at `partCentre`, never at `cell`. `isWheelType` covers all four wheels (`smallWheel` 0.5, `wheel`, `mediumWheel` 1.5 and `bigWheel` 2: `WHEEL_SIZES` / `wheelSizeOf`; the small and medium ones take one cell, and a wheel smaller than the normal one hangs lower in it, `wheelDrop` in `partCentre`, which also slides a wheel whose axle crosses the block's face in until its inner side is `WHEEL.gap` from the block; `Grid.canPlace` rejects a wheel whose `wheelBox` overlaps another wheel's; `torque` there scales with ~`scale`⁴ because the motor is acceleration based).
- Wheel chain: `chassis -prismatic spring- hub -revolute- wheel` (`SUSPENSION`, `Part.suspension`, set only in `PartInspector`); the spring must stay `ForceBased` and scaled by the supported mass, an acceleration-based one cannot hold the chassis. The vehicle controller drives the hub-wheel revolute joint; the hub needs a large rotational inertia (`SUSPENSION.hubInertia`) or the engine is too weak and A / D stop steering.
- Orientation: see Rotation above; `face` only says where a wheel / engine is mounted. A wheel's Rapier body must stay unturned, so a wheel carries its turn in the pivot of its visual (`createPartObject`), not on the root. `studsEngaged` requires equal stud directions. **Keep `help-content.ts` in sync.**
- Siren (`'siren'`, a beacon: mounted on a block face like the lamp, `SIREN` / `SIREN_BODY` / `SIREN_VISUAL`, `parts/siren-model.ts` (`setSirenLevel`), `PART_ACTIONS.siren` toggle `run`): `PhysicsWorld.flashSirens` fades it and flashes its red / blue halves, `VehicleSound` wails while `AudioState.sirens` is lit; a look and a sound only. Category `'lighting'` (`PartCategory`, `PART_CATEGORIES`) with the lamp: new lights go there. **Keep `help-content.ts` and `docs/` in sync.**
- Lamp (`'lamp'`, a headlight: mounted on a block face like the propeller, front = +z = the way it shines, `LAMP` / `LAMP_BODY` / `LAMP_VISUAL`, `parts/lamp-model.ts` (`setLampLevel`), `PART_ACTIONS.lamp` toggle `run`): `PhysicsWorld.fadeLamps` fades its lens glow and beam with the key; a look only (no real light, no physics beyond `LAMP.mass`); sounds `lampOn` / `lampOff` from `VehicleSound` (`AudioState.lamps`). **Keep `help-content.ts` and `docs/` in sync.**
- Ballast (`'ballast'`, a 1x1x1 structural cube with a fixed density `BALLAST.density` x the default block's: `weightUnits` / `PART_INFO.ballast.hasWeight = false`, amber band in `createPartObject`, not a host): use `weightUnits(part)` (not `weightOf`) wherever a structural part's mass is computed. **Keep `docs/` and `help-content.ts` in sync.**
- Tiles (`tileQuarter`, `tileHalf`, `tile`, `tileLong`, `tileLarge`; `ShapeBox.smooth` in `part-shapes.ts`): plates with no studs on top, only sockets underneath: like a wedge `studsEngaged` only lets a tile be the held part (`!boxA.smooth`), `part-defs.ts` draws no studs on it; otherwise a plain flat box (also `isFlatStructural`). **Keep `docs/` and `help-content.ts` in sync.**
- Round parts (`roundBrick`, `roundPlate`, `roundBrickLarge`; `ShapeBox.round` in `part-shapes.ts`): a cylinder inscribed in the shape's square box (axis = studs direction): it occupies the box (`partBoxes`), but only the studs inside the circle exist (`studInside`; drawn by `studsGeometry` / `socketsGeometry` with `round`, counted one by one in `studsEngaged` via `studsBetween`), `partVolume` is the cylinder's, and `PhysicsWorld.addStructuralColliders` makes a real cylinder collider. Not hosts and not `isFlatStructural`. **Keep `docs/` and `help-content.ts` in sync.**
- Glass (`glass`, `glassLarge` flat panes, `windscreen`, `windscreenLong` wedges; `isGlass`, `glassMat` in `part-defs.ts`, `ALPHA.glass`, `COLORS.part.glass`): ordinary structural parts (plate / slope shapes and physics) drawn translucent; painted glass keeps its alpha. `isFlatStructural` excludes the windscreens. Keep `docs/` and `help-content.ts` in sync.
- Wedges / slopes (`ShapeBox.wedge`, `slope*` types in `STRUCTURAL_TYPES`): triangular prisms with sockets underneath and NO studs on the slope (`studsEngaged` only lets them be held), bounding-box occupancy, a convex-hull collider from `wedgePoints`, `partVolume` halved. They are not hosts. **Keep `docs/` and `help-content.ts` in sync.**
- Part names: structural parts are `<studs wide>x<studs long> <Kind>` (kinds: Block, Plate, L bracket, Slope, Slope Plate) (`2x2 Block`, `1x2 Plate`, `4x4 L bracket`; top-face studs, narrow side first, no height except `Low` (3 plates, 0.6) / `Tall` (2 cells) variants: `2x2 Low Block`; see `docs/adding-a-part.md`); `PartType` keys keep the old names (saved games). Use the pattern for new sizes.
- Structural parts (`STRUCTURAL_TYPES`: block, the 1x1 / 1x2 / 1x4 / 2x4 / 4x4 blocks and their low (0.6) and tall (2 cells) variants, plate, the 1x1 / 1x2 / 1x4 / 2x4 / 4x4 / 4x8 plates, and the 1x2 / 2x2 / 2x4 / 4x4 L brackets) are described by `SHAPES` (`constants/part-shapes.ts`: boxes with a studs direction each, anchor = first box = `Part.cell`, `spins`); orientation = `Part.studs` + `Part.spin` (`parts/orientation.ts`); use `partBoxes` / `relativeBoxes` / `partsOverlap`, not a single box, and `isStructural(type)`. Mounted parts go on any block (see below). **Keep `docs/` and `help-content.ts` in sync.**
- Studs (`STUD`, `parts/part-geometry.ts`): blocks and plates snap to the stud pitch (x / z half cells) and are welded only through engaged studs (`Grid.linkedParts`, also what `PhysicsWorld` flood-fills); `Grid.canPlace` needs the ground or `engagedStuds > 0`; there is no cell index: use `partBoxes` / `partsOverlap`, compare positions with `cellKey` / `EPS`. Plate (`'plate'`, `PLATE.thickness`): a thin block with studs (flat, or a wall when tilted); use `isStructural(type)` (block or plate) wherever "part of the body" is meant, and `partVolume` for mass.
- Engine (`'engine'`, NOT structural: mounted on a block face like a wheel, `face` + `front` + `power`, `ENGINE`, `ENGINE_BODY`, `isMountedType`, `Grid.mountedOn` / `enginesOnBody`): with `Grid.engineDrive` (true for new games, saved in `SaveGame.engineDrive`; old saves drive every wheel) a wheel is powered only by the engines of its body, pushing towards their front (turned around = reversed, sideways = nothing); power is shared among the body's wheels (`WheelDrive.engines`, `VehicleController`). Position matters: `PhysicsWorld.applyEngines` turns each engine's push into a torque about the body's centre of mass (`ENGINE.leverage`, `PhysicsWorld.throttle`), so a high or off-centre engine pitches / turns the vehicle. Wheels, engines, turbos, thrusters, rotors, pistons and hinges mount on any block (`HOST_TYPES` / `isHostType`: every block, low and tall ones included; not plates and brackets); `Part.cell` of a mounted part is the unit cell against the face, centred on the pointer in half-cell steps when the face is wider than a cell, and its host is `Grid.hostOf(part)` (the block whose face contains `cell - face / 2`), never `cell - face`; an engine's front may not point into its block and it may not be upside down (heads down) (`Grid.canPlace`). **Keep `help-content.ts` and `docs/` in sync.**
- **Part keys** (`Part.keys`: action id -> `KeyboardEvent.code`s; `src/constants/part-keys.ts` `PART_ACTIONS`, `Grid.editKeys` / `assignKeys`, `ui/key-capture.ts`, the key section of `PartInspector`, the bell + `ui/alerts-dialog.ts`): **a rule of the game: no part has a default key and every mobility part needs keys assigned by the player to do anything** (the engine's Accelerate / Reverse, a wheel's Steer left / right and Brake, the `run` of a rotor, piston, thruster and turbo; W A S D and the arrows drive nothing by themselves). An action can have several keys; parts with the same key work together; hold-vs-toggle is decided per action in `PART_ACTIONS`; actions without a key, required or optional, are counted by the bell (`partsToCheck`); the panel lists the required ones first (`lacksKey`). `VehicleController.isOn(part, action)` / `engineInput` / `steerInput` say what runs (`PhysicsWorld.isOn` / `engineInput`); never hard-code a key for a part. Only R / P / H / M are `RESERVED_KEYS`; editing keys (I, B, C...) may be assigned. Games without engines (`engineDrive` false) keep fixed W / S / A / D (`LEGACY_KEYS`). **A new mobility part gets its actions in `PART_ACTIONS` (label, mode, required), `help-content.ts` and `docs/`.** **In-air attitude control is the wings' `pitchUp` / `pitchDown` / `rollLeft` / `rollRight` / `yawLeft` / `yawRight` actions (the old fixed pitch / roll / yaw keys are gone).**
- Driving assist: `PhysicsWorld.straighten` (heading hold while the player does not steer; `VEHICLE.straighteningGain`, `PhysicsWorld.steering`) and `PhysicsWorld.drag` (`VEHICLE.airDrag`) act on the bodies that carry wheels; the simulation veers a little on its own, so keep them when you change the wheels.
- Thruster (`'thruster'`, like the engine: mounted on a block face, `Part.power` = thrust, `THRUSTER`, `THRUSTER_BODY`, `MOUNTED_BODY`, `Grid.thrustersOnBody`): its key (`Part.keys.run`, hold) makes `PhysicsWorld.applyThrust` push its host body along its front at the place where it is mounted. **Keep `help-content.ts` and `docs/` in sync.**
- Propeller (`'propeller'`, like the thruster: mounted on a block face, `Part.power` = thrust, `PROPELLER`, `PROPELLER_BODY`, `PROPELLER_VISUAL`, `parts/propeller-model.ts` (the blades group `PROPELLER_BLADES` is spun by `PhysicsWorld.applyPropellers`), `MOUNTED_BODY`, `Grid.propellersOnBody`; its key `run` is a toggle and its thrust fades to 0 at `PROPELLER.maxAirSpeed`) and wings (`'wing'` 4x3 and `'wingLarge'` 8x6: structural swept wings in the *Mobility* category, a single `ShapeBox` with a convex `polygon`, flat and the same on both faces with sockets on both (`studBoxesOf`), so turned over a wing is its own mirror image and there is no left / right pair; see `swept` in `part-shapes.ts`; `isWing`, `WING_TYPES`, `WING`; front edge = local +z, lift towards the face that is up at spawn), `isWing`, `WING_TYPES`, `WING`; front edge = local +z, lift towards local up): `PhysicsWorld.applyWings` applies lift (`sin(2a)`) and drag at each wing from the velocity of its body at that point, so a wing on a rotor head is a helicopter blade, and each wing's six optional hold actions `pitchUp` / `pitchDown` / `rollLeft` / `rollRight` / `yawLeft` / `yawRight` (`PART_ACTIONS`) move its control surface the way that turns the plane as asked from where it is (`buildWingControls`); these actions are the plane's attitude control (**never fixed keys**). Bodies with wings or propellers are in `aero` (skipped by the air-drag assist). **Keep `help-content.ts` and `docs/` in sync.**
- **Placement never corrects a part's orientation**: the ghost takes the orientation the player chose (A / D, W / S) and only turns red when `Grid.canPlace` says no (engine front into the block, upside-down engine, rotor head pointing at the block…). Do not auto-orient new parts.
- Spring (`'spring'`, a passive piston: same machinery as the piston, no key; `Part.stroke` = rest length, `Part.stiffness` 1-10, `SPRING`, `springRate`, `PART_INFO.hasStiffness`, `Grid.setStiffness`, `SPRING_VISUAL` / `SPRING_BODY`, `createSpringCoil`): its joint is force based, so the load decides how far it sinks (`sag ≈ load · gravity / springRate`); an entry of `PhysicsWorld.pistons` with `spring`. A spring may also be mounted on any flat structural part, plates and L brackets included, on the faces of their individual boxes (`isFlatStructural`, `canHost`, `isMountHost` in `types.ts`, `Grid.hostOf` / `BuildMode.target` check box by box; not on slopes or wings; every other mounted part needs a block, `HOST_TYPES`). **Keep `help-content.ts` and `docs/` in sync.**
- Piston (`'piston'`, like the rotor, NOT structural: `Part.stroke` 1-6 half cells, `PISTON`, `PISTON_VISUAL` / `PISTON_BODY`, `headOf` / `isHeaded` shared with the rotor): its head (stud box) holds a separate body joined by a prismatic joint; its key (toggle) pushes it out / back (`VehicleController.isOn`, `PhysicsWorld.isOn`), the rod is rescaled each frame. **Keep `help-content.ts`, `play-controls.ts` and `docs/` in sync.**
- Hinge (`'hinge'`, a headed part like the rotor and the piston: mounted on a block face, NOT structural, its head (stud box, `headOf`) holds a separate body; `Part.angle` 1-12 steps of 15° (default 6 = 90°) and `Part.strength` 1-10 (the servo's stiffness, default 5), `HINGE`, `HINGE_VISUAL` / `HINGE_BODY`, `hingePivot`, `hingeAngleOf`): a revolute joint on the pin along one edge with limits [0, π] and a position motor towards the open angle while its `run` action (toggle) is on (`PhysicsWorld.driveHinges`). Its studs must point away from the block (`Grid.canPlace`), it is placed with the orientation the player chose, and its 4 spins are different (they choose the edge with the pin). **Keep `help-content.ts` and `docs/` in sync.**
- Rotor (`'rotor'`, mounted on a block face like the engine, NOT structural: `Part.speed` -10..10 (sign = direction), `ROTOR`, `ROTOR_VISUAL` / `ROTOR_BODY`, `rotorHead` in `part-geometry.ts` (its head is a stud box, so parts on it are held by it), `Grid.linkedParts` skips it, `PhysicsWorld.buildRotors`): the structural parts engaged with its head are a separate body joined to the block's by a motorised hinge (contacts off) and turn with the head when its key (toggle) switches it on (`VehicleController.isOn`). Its studs (local up) must point away from the block (`Grid.canPlace`); like every part it is placed with the orientation the player chose and is never turned for them. **Keep `help-content.ts` and `docs/` in sync.**
- Turbo (`'turbo'`, like the engine: mounted on a block face, `Part.power` = boost, `TURBO`, `TURBO_BODY`, `MOUNTED_BODY`, `isCompactMounted`, `Grid.turbosOnBody`): its key (hold) boosts the driven wheels of its body (`WheelDrive.turbos`, `VehicleController`); the engine and the turbo share the power slider and `setPower`. **Keep `help-content.ts` and `docs/` in sync.**
- Ski (`'ski'`, `isSki`, like a wheel: mounted on a side face, takes its cell (`partBox` is the cell), optional steering keys (`PART_ACTIONS.ski`: `steerLeft` / `steerRight`, `PhysicsWorld.steerSkis`: the runner `SKI_RUNNER` turns up to `SKI.maxSteer` and an edge impulse `SKI.grip` removes the sideways velocity across it), `SKI` / `SKI_BODY`, `parts/ski-model.ts`): a rounded hull collider (`roundConvexHull`, `SKI.round`: a sharp-edged one hops at speed) on the host body with friction `SKI.friction` and combine rule `Min`; `Grid.canPlace` requires studs up and its length (`frontOf`) along the face, and its arm side depends on face + orientation, so `createPartObject` needs `face` / `studs` / `spin` (the ghost is rebuilt when they change). the sled assist `PhysicsWorld.levelSkis` (`SKI.levelGain` / `levelMin` / `levelGrace`) keeps a grounded body on skis level (follows the contact normal) so it does not tumble. **Keep `help-content.ts` and `docs/` in sync.**
- Brake (NOT a part: every wheel has one, `Part.brake` 1-10 default `BRAKE.default`, `Grid.setBrake`, `brakeOf`, `brakePose`, slider in `PartInspector.brakeSection`): the wheel's Brake key (`Part.keys.brake`, optional, hold; `lacksKey` ignores wheels) holds the wheels that have it (`WheelDrive.brake` / `part`, `VehicleController`). **Keep `help-content.ts` and `docs/` in sync.**
- Block weight (`WEIGHT`, `Part.weight`, slider in `PartInspector`, `Grid.setWeight`): block collider density = `CHASSIS.density × weightMass(weight)`; default weight 4 = ×1 so nothing changes for old saves.
- Tires (`TIRE`, `Part.tire` 0-100, a slider only in `PartInspector`) set wheel friction, top speed and motor torque, interpolated between three points; keep `torque` scaled with `friction`, or high-grip tires cannot skid-steer.
- A wheel body must start **un-rotated**: Rapier's revolute joint uses the same axis numbers in both bodies'
  local frames, so only the wheel's *collider* and mesh are rotated toward the axle.
- Wheels (radius 0.65) collide only with the ground; this is done with collision groups, keep it that way.
- Tuning constants (speed, motor strength, brake, steering, friction, gravity) live in `src/constants/physics.ts` and are listed in `docs/physics.md`.

## Verifying changes

Full checklist in [docs/testing.md](docs/testing.md). **Always test with the game muted** (`M`, check `#btn-sound.muted`; saved in `localStorage` `buildblock.sound`).

1. `npm run build` must pass.
2. Run `npm run dev`, open the app and exercise the feature: place blocks/wheels with real clicks, press
   Play, drive with W/S/A/D, `R` restarts, Stop returns to the intact build.
3. Dev mode exposes `window.__buildblock` (`grid`, `camera`, `controls`, `getPhysics()`, `getMode()`, `menuScene`, `build`, `history`, `zoom`) for inspecting
   state, e.g. a body's position, from the console.
4. The in-app browser pane pauses `requestAnimationFrame` while hidden; if physics seems frozen, bring the
   tab to the front (a screenshot also wakes it) before concluding something is broken.
